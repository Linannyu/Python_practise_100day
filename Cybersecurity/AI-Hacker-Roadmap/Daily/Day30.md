## Part 2 — 概念自测

不用查看答案，先用自己的话解释：

```text
Request 与 Response
GET 与 POST
参数与请求头
Cookie 与 Session
Authentication 与 Authorization
SQL Injection 的根本原因
Reflected XSS 的根本原因
IDOR 缺少的检查
状态码 200、302、404
AI 假设与人工证据的区别
```

### 我的回答

- **Request 与 Response：** Request（请求）是浏览器或程序发给服务器的信息；Response（响应）是服务器回来的结果，例如状态码、响应头和页面内容。
- **GET 与 POST：** GET 常把查询数据放在 URL 中，用于读取或查看；POST 常把数据放在请求正文中，用于提交。两者是通信方式，不代表其中任何一种天然更安全。
- **参数与请求头：** 参数是某个功能需要的具体输入，例如分类或页码；请求头是附加说明，例如客户端希望接收的内容类型。它们都不能代替服务器自己的验证。
- **Cookie 与 Session：** Cookie 是浏览器保存并随请求发送的小数据；Session 是服务器保存的访问状态。Cookie 可以携带识别某个 Session 的值，但两者不是同一个东西。
- **Authentication 与 Authorization：** Authentication 先确认“你是谁”；Authorization 再确认“你是否有权限做这件事”。登录成功不等于可以访问所有资料或管理功能。
- **SQL Injection 的根本原因：** 程序把不可信输入直接拼进 SQL 语句结构，导致数据可能被当成 SQL 语法。修复方向是参数化查询和服务端输入处理。
- **Reflected XSS 的根本原因：** 程序把不可信输入放回 HTML 页面时，没有按照所在位置做正确的输出编码，使输入可能被浏览器当成页面代码解释。修复方向是上下文相关的输出编码。
- **IDOR 缺少的检查：** 服务器根据客户端给出的对象标识取数据，却没有确认当前已登录用户是否有权访问那个对象。
- **状态码 200、302、404：** `200` 表示服务器成功返回了本次请求的响应；`302` 表示服务器让客户端跳转到另一个位置；`404` 表示服务器没有找到请求的资源。状态码必须结合响应内容理解。
- **AI 假设与人工证据的区别：** AI 假设是“可能发生什么”的预测；人工证据是我在本地代码或授权环境中实际观察到的输出、记录或官方说明。证据可以支持、否定或限制假设。
