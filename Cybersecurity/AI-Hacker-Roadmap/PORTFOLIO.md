# AI Hacker Roadmap — 学习作品集

这是一个从零开始的 30 天 Web 安全学习项目，已完成 Day 1–Day 30。所有实验均限于本地页面和明确授权的教学靶场；这里不保存 Cookie、密码、Token、临时实验地址或个人信息。

## 我完成了什么

- 完成了 30 个每日学习任务：从 HTTP 请求结构、Cookie 与 Session，到 Python 工具、AI 验证、脱敏报告与最终复盘。
- 在官方授权靶场完成了 6 个基础实验，并保存必要的脱敏学习记录。例如 [Day 14 证据](Labs/PortSwigger/Day14/README.md) 和 [Day 28 证据](Labs/PortSwigger/Day28/README.md)。
- 编写了三个小型 Python 工具：HTTP 响应摘要、URL 解析和本地代码验证检查。它们的范围受允许列表和固定示例限制。
- 写了一份结构化的脱敏报告：[Day 27 报告](Reports/Day27-first-report.md)。

## 我能解释什么

- HTTP 请求与响应的基本组成，以及 GET、POST、URL 查询参数、请求头和响应状态码的作用。
- 为什么登录（Authentication）和权限判断（Authorization）是不同的事情；为什么关键规则不能只依赖浏览器页面。
- SQL、XSS、认证和访问控制问题的基础风险，并且只在授权教学环境中理解和验证它们。
- 如何把 AI 的建议当作假设：先指出可观察证据，再用代码输出、请求结果或官方说明验证。
- 如何写一份安全记录：说明范围、事实、影响和修复方向，同时隐藏敏感数据。

## 我下一步要学习什么

下一阶段的主线是 **安全代码审查与防御修复**：

1. 加强 Python 基础：函数、文件处理、异常处理和自动化测试。
2. 用本地教学代码练习识别输入处理、权限判断和输出编码问题，再写出防御性修复。
3. 为每次修复添加可重复的本地测试，并记录修复前后有什么不同。
4. 完成 3 个本地代码审查案例、3 个带测试的修复和 1 份脱敏安全编码总结报告。
5. 继续只在自己搭建的环境或明确授权的平台练习，并在每次记录前做脱敏检查。
